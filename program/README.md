Консольная дискретно-событийная имитационная модель серверной системы обработки поисковых запросов интернет-магазина. Программа написана на JavaScript и не требует сторонних библиотек.

## Запуск

Требуется Node.js версии 20 или новее.

**Windows:** запустить `start.bat` двойным щелчком.

**Из терминала VS Code:**

```powershell
node src/cli.js
```

**Запуск тестов:**

```powershell
node --test
```

или `test.bat` в Windows.

## Режимы работы

### Пошаговый режим (ОД1)

Одно нажатие Enter обрабатывает одно ближайшее особое событие. После каждого события отображаются:

- модельное время и тип события;
- состояние источников и число созданных заявок;
- все ячейки буфера и оба циклических указателя;
- состояние приборов, текущие заявки и время занятости;
- текущие показатели по источникам и действия, выполненные на шаге.

Для возврата в меню введите `q`.

### Автоматический режим (ОР1)

Программа выполняет моделирование до завершения генерации заданного количества заявок и последующего обслуживания всех заявок, оставшихся в системе. Выводятся две итоговые таблицы:

1. характеристики источников: N, Pотк, Tпреб, Tож, Dож, Tобсл, Dобсл;
2. коэффициенты использования приборов Kисп.

## Расшифровка варианта

| Код | Правило | Реализация |
|---|---|---|
| ИБ | Бесконечный источник | Источники создают заявки до достижения общего лимита N. |
| ИЗ1 | Пуассоновский поток | Интервалы между поступлениями имеют экспоненциальное распределение Exp(λ). |
| ПЗ2 | Равномерное обслуживание | Время обработки выбирается из U(t_min, t_max). |
| Д1ОЗ1 | Постановка по кольцу | `putPointer` задаёт начало поиска свободной ячейки. |
| Д1ОО3 | Вытеснение старейшей заявки | При заполнении буфера удаляется ожидающая заявка с минимальным временем генерации. Новая заявка занимает освободившуюся ячейку. |
| Д2П1 | Приоритет прибора по номеру | Выбирается первый свободный прибор при проверке по возрастанию номера. |
| Д2Б3 | Выбор заявки по кольцу | `selectionPointer` задаёт начало поиска первой занятой ячейки. |
| ОД1 | Пошаговое состояние | После каждого события показываются источники, буфер, указатели, приборы и текущие показатели. |
| ОР1 | Итоговые таблицы | После автоматического прогона выводятся характеристики источников и приборов. |

## Логика модели

Используется общая буферная память фиксированной ёмкости. Все источники помещают заявки в один буфер.

Диспетчер постановки работает только с буфером и статистикой. При поступлении заявки он ищет свободную позицию по кольцу. Если буфер заполнен, вытесняется заявка с самым ранним временем генерации `generatedAt`; при равенстве времени используется меньший `sequenceId`.

Диспетчер выбора запускается после помещения заявки в буфер и после освобождения прибора. Пока в буфере есть заявки и доступны приборы, он выбирает первый свободный прибор по Д2П1, извлекает заявку по Д2Б3 и начинает обслуживание.

Моделирование выполняется по особым событиям. Внутренний календарь событий упорядочивает поступления и завершения обслуживания по модельному времени. После генерации N новых поступлений больше нет, но уже принятые заявки продолжают обслуживаться. Модель завершается, когда буфер пуст и все приборы свободны.

## Параметры

Параметры можно изменить в пункте меню «Изменить параметры»:

| Параметр | Значение по умолчанию |
|---|---:|
| Количество источников | 3 |
| Интенсивность каждого источника λ | 0,22 |
| Количество приборов | 3 |
| Ёмкость буфера | 8 |
| Минимальное время обслуживания | 3 |
| Максимальное время обслуживания | 7 |
| Общее количество заявок N | 500 |
| Seed генератора случайных чисел | 42 |

Численные значения по умолчанию используются для демонстрационного запуска; их можно менять перед экспериментами.

## Расчёт показателей

Для каждого источника:

- `Pотк = Nвытеснено / Nсгенерировано`;
- `Tож = время начала обслуживания − время постановки в буфер`;
- `Tобсл = время завершения − время начала обслуживания`;
- `Tпреб = время завершения − время генерации`;
- `Dож` и `Dобсл` — выборочные дисперсии соответствующих времён.

Вытесненные заявки учитываются в Pотк, но не включаются в средние времена ожидания, обслуживания и пребывания успешно обработанных заявок.

Для каждого прибора:

`Kисп = накопленное время занятости прибора / общее время реализации`.

## Общая и зонная буферная память

**Общий буфер** используется, когда все источники работают с одной общей очередью и любая свободная ячейка доступна любому источнику. **Зонный буфер** целесообразен, когда требуется разделить потоки по источникам или зарезервировать для них отдельные области памяти. В этой модели используется общий буфер.

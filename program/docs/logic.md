# Логика реализации по диаграммам

## Main Flow

1. Внутренний `EventCalendar` хранит будущие `ARRIVAL` и `SERVICE_COMPLETION`; `SimulationEngine` извлекает ближайшее событие.
2. При `ARRIVAL` движок вызывает `Source.generateRequest`.
3. Источник создаёт `Request`; движок планирует следующее поступление по `Exp(λ)`, если общий лимит N ещё не достигнут.
4. `Statistics.recordGenerated` регистрирует поступление.
5. `PlacementDispatcher.handleArrival` ищет свободную позицию через `Buffer` по `putPointer`.
6. Если буфер заполнен, `Buffer.evictOldest` удаляет ожидающую заявку с самым ранним `generatedAt`; `Statistics.recordEvicted` фиксирует вытеснение; новая заявка занимает освободившееся место.
7. После помещения заявки движок вызывает `SelectionDispatcher` по триггеру `REQUEST_ENQUEUED`.
8. При `SERVICE_COMPLETION` движок освобождает `Worker`, регистрирует завершение и вызывает `SelectionDispatcher` по триггеру `SERVICE_COMPLETED`.
9. `SelectionDispatcher`, пока есть заявки и свободные приборы, выбирает первый свободный `Worker` по номеру, извлекает первую занятую ячейку от `selectionPointer`, начинает обслуживание и помещает `SERVICE_COMPLETION` во внутренний календарь.
10. Модель завершается после генерации N и выхода всех заявок из буфера и приборов.

## Happy Flow

Буфер имеет свободную позицию; новая заявка записывается по Д1ОЗ1; после триггера `REQUEST_ENQUEUED` `SelectionDispatcher` находит свободный `Worker` по Д2П1; `Buffer` извлекает заявку по Д2Б3; `Worker` начинает обслуживание длительностью `U(t_min, t_max)`; в календарь добавляется `SERVICE_COMPLETION`.

## Overflow

Когда все приборы заняты и буфер заполнен, новая заявка всё равно генерируется. `PlacementDispatcher` получает `FULL`, вытесняет самую старую ожидающую заявку по `generatedAt` (Д1ОО3), обновляет статистику отказов и размещает новый запрос. Затем запускается `SelectionDispatcher`; свободных приборов нет, поэтому новая заявка остаётся в буфере до следующего `SERVICE_COMPLETION`.

## Кольцевые указатели

Индексы внутри программы нулевые; в пошаговом интерфейсе отображаются номера ячеек с единицы. После постановки в ячейку `i`:

`putPointer = (i + 1) mod B`

После извлечения заявки из ячейки `i`:

`selectionPointer = (i + 1) mod B`

Поиск проходит максимум B ячеек и не может зациклиться бесконечно.

## Отображение

- Пошаговый режим: строго одно особое событие на одно нажатие; после него обновляются источники, все ячейки общего буфера, оба указателя, приборы и текущие показатели. Отдельная таблица календаря и графики не выводятся.
- Автоматический режим ОР1: выводятся только две итоговые таблицы — по источникам и по приборам. Графиков нет.

Внутренний `EventCalendar` не является элементом экранного пошагового отчёта; он используется моделирующим алгоритмом для упорядочивания событий по времени.

## Распределения

Экспоненциальный интервал между поступлениями:

`T = -ln(1 - U) / λ`, где `U` равномерно распределено на [0; 1).

Равномерное обслуживание:

`Tобсл = t_min + U · (t_max - t_min)`.

Один `seed` обеспечивает воспроизводимость реализации при неизменных параметрах.

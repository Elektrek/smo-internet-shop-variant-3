# Проверка первичных артефактов перед защитой

- [ ] В основном сиквенсе показана генерация заявки по ИБ/ИЗ1.
- [ ] `Д1ОЗ1`: кольцевая постановка; ответы буфера показаны пунктирными response-сообщениями.
- [ ] `Д1ОО3`: при переполнении вытесняется только самая старая ожидающая заявка; вытеснение отражается в статистике.
- [ ] `Д2Б3`: выборка выполняется от указателя выборки по кольцу.
- [ ] `Д2П1`: свободный прибор ищется по возрастанию номера; приборы только свободны или заняты.
- [ ] `ПЗ2`: время обслуживания выбирается из равномерного распределения.
- [ ] Отдельно показаны Happy Flow, переполнение, операции буфера и назначение на прибор.
- [ ] Диспетчер постановки имеет ссылку на буфер и принимает `Request`; он не содержит ссылки на `DevicePool`.
- [ ] Диспетчер выбора связан с `Buffer`, `DevicePool`, `EventCalendar` и `Statistics`.
- [ ] В диаграмме классов детали реализации скрыты приватными полями, а методы и связи обозначены.
- [ ] Flowchart имеет дорожки компонентов и показывает альтернативы.
- [ ] Пошаговый режим сохраняет таблицу календаря и снимок состояния после каждого события.
- [ ] До программирования сверены с методичкой определения кодов `Д1ОЗ1`, `Д1ОО3`, `Д2П1`, `Д2Б3`.
- [ ] До экономического вывода выполнены серии прогонов для разных `M` и `B`, а тарифы/стоимость потери запроса обоснованы источниками.

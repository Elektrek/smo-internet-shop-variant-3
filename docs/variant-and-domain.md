## 1. Бизнес-домен

Моделируется серверная система, которая принимает поисковые запросы из веб-приложения, мобильного приложения и внешних интеграций интернет-магазина. Запрос содержит поисковую строку, набор фильтров, идентификатор источника и временные отметки. Вычислительные процессы выполняют поиск по индексу, фильтрацию каталога и формирование ответа.

Система представлена как СМО с несколькими независимыми генераторами заявок, общим ограниченным буфером и `M` приборами обслуживания. В модели прибор — это вычислительный worker-процесс, который может обслуживать не более одной заявки одновременно.

## 2. Элементы модели

| Элемент СМО | Реализация в предметной области | Ответственность |
|---|---|---|
| Источник | Веб-клиент, мобильный клиент или API-интеграция | Создаёт заявки по закону `ИЗ1` |
| Заявка | Поисковый запрос с фильтрами | Хранит ID, источник, времена генерации/постановки/старта/завершения и статус |
| Буфер | Общая очередь фиксированной ёмкости `B` | Хранит ожидающие заявки; поддерживает кольцевые указатели |
| Диспетчер постановки | Приём входящей заявки | Помещает заявку в буфер; при переполнении применяет `Д1ОО3` |
| Диспетчер выбора | Планировщик обслуживания | Реагирует на триггеры и назначает заявки приборам |
| Прибор | Worker-процесс поиска | Выполняет один запрос за случайное время по `ПЗ2` |
| Календарь событий | Очередь событий по модельному времени | Определяет следующее событие для обработки |
| Статистика | Счётчики и агрегаты измерений | Считает отказы, ожидание, время в системе и загрузку |
| Пошаговое представление | Таблица состояния СМО | Реализует `ОД1` |
| Отчётчик | Сводная таблица результатов | Реализует `ОР1` |

## 3. Законы и дисциплины

1. Для каждого источника `i` интервал между заявками имеет экспоненциальное распределение: `T_arr,i ~ Exp(lambda_i)`. Суммарный входной поток независимых источников также пуассоновский с интенсивностью `sum(lambda_i)`.
2. Время обслуживания заявки: `T_service ~ U(t_min, t_max)`.
3. При постановке используется кольцевой поиск свободной ячейки от `putPointer` (`Д1ОЗ1`). После вставки указатель перемещается на ячейку после занятой позиции по модулю `B`.
4. При заполненном буфере вытесняется самая старая **ожидающая** заявка (`Д1ОО3`). Обслуживаемая заявка не может быть вытеснена.
5. Заявка выбирается из буфера поиском первой занятой ячейки, начиная с `selectionPointer` по кольцу (`Д2Б3`). После извлечения указатель сдвигается на позицию после извлечённой.
6. Свободный прибор определяется по возрастанию номера (`Д2П1`). Приборы не отказывают; состояние прибора — только `FREE` или `BUSY`.
7. Диспетчер постановки не получает ссылку на пул приборов. Решение об обслуживании принимает только диспетчер выбора.
8. Пакетная обработка не применяется, поскольку код варианта описывает кольцевую выборку заявки, а не группирование в пакеты.

## 4. Предметные состояния заявки

`GENERATED → BUFFERED → IN_SERVICE → COMPLETED`.

Альтернативный путь: `BUFFERED → EVICTED`. Заявка со статусом `IN_SERVICE` не может перейти в `EVICTED`. Если буфер не переполнен, входящая заявка помещается в свободную ячейку. При переполнении сначала вытесняется старейшая ожидающая заявка, затем размещается новая.

## 5. Метрики

- Доля отказов: `N_evicted / N_generated`.
- Среднее ожидание: среднее `serviceStartedAt − enqueuedAt` по завершённым заявкам.
- Среднее время в системе: среднее `completedAt − generatedAt` по завершённым заявкам.
- Загрузка прибора `j`: время занятости `j` / длительность моделирования.
- Пропускная способность: количество завершённых заявок / длительность моделирования.
- Максимальная длина очереди: максимум числа занятых ячеек буфера в истории модели.

Оптимизация параметров проводится экспериментально. Требуется подобрать `M` и `B`, при которых доля отказов не превышает 10%, загрузка приборов близка к 90%, а среднее время пребывания в системе мало. Утверждать конкретный оптимум до запуска симуляций нельзя.
